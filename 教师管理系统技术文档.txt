## 1. 项目概述
### 1.1 背景与目标
为满足一所大数据与AI培训学校的教职工管理需求，开发一套集基础信息管理、课程安排、事务审批、考勤打卡、消息推送及智能助手于一体的教师管理系统。系统以Python/FastAPI为后端，MySQL为关系数据库，Milvus为向量数据库，基于LangChain构建具有古典诸葛亮形象的智能Agent，实现自然语言操作、知识问答与游戏互动。

### 1.2 核心功能
- 教职工信息管理（CRUD+软删除）
- 认证与权限控制（两层角色）
- 课程表管理（冲突检测）
- 事务申请与审批（流程化）
- 考勤打卡（规则自动判定）
- 消息中心与主动推送（课程提醒、生日祝福）
- 操作日志记录（全链路审计）
- 诸葛亮Agent（LangChain工具调用、NL2SQL、RAG、游戏、多轮对话）
- 报表导出（Excel格式）
- 文件上传（头像、附件，安全校验）

### 1.3 技术栈
| 类别 | 技术选型 |
|------|----------|
| 后端 | Python 3.11+，FastAPI 0.110+，SQLAlchemy 2.0（异步），Alembic |
| 数据库 | MySQL 8.0，Milvus 2.4 |
| 缓存/会话 | Redis 7.2（序列号、会话、验证码、Agent状态） |
| 大模型 | DeepSeek-V4-Pro（复杂推理/NL2SQL），DeepSeek-V4-Flash（快速响应/RAG） |
| 向量化 | DeepSeek Embedding API |
| Agent框架 | LangChain 0.2+ |
| 前端 | Vue 3 + Element Plus（古典风主题） |
| 部署 | Docker Compose，Nginx反向代理 |

## 2. 系统架构
```
┌───────────────┐      ┌───────────────────────────────────────────┐
│   前端 (Vue)   │◄────►│  FastAPI 后端服务                          │
│  古典风 UI     │ HTTP │  ├─ 全局异常处理层                        │
│  语音输入      │ SSE  │  ├─ 认证/限流/日志中间件                  │
│  Agent对话     │      │  ├─ 业务路由 (CRUD)                       │
└───────────────┘      │  ├─ LangChain Agent服务                   │
                       │  │   ├─ 工具管理器 (NL2SQL/RAG/搜索/游戏) │
                       │  │   ├─ 会话管理器 (Redis)                 │
                       │  │   └─ 意图识别与路由                    │
                       │  ├─ 消息推送服务 (后台任务)                │
                       │  └─ 报表/文件模块                         │
                       └──────────┬────────────────────────────────┘
                                  │
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
        ┌─────────┐        ┌──────────┐        ┌──────────┐
        │  MySQL  │        │  Milvus  │        │  Redis   │
        │ 教师/课程 │        │ 知识库   │        │ 缓存/序列号│
        │ 事务/打卡 │        │ 规章制度 │        │ 会话/验证码│
        │ 软删除标记│        │ 文档向量 │        │ Agent状态 │
        └─────────┘        └──────────┘        └──────────┘
```

**通信方式**：前端与后端通过RESTful API交互，Agent对话采用SSE流式响应（支持长连接和实时输出）。  
**异步任务**：消息推送、生日检测、报表生成采用FastAPI BackgroundTasks，后期可平滑迁移至Celery。  
**全局异常处理**：所有请求经过异常处理层，统一捕获并返回标准化错误响应，避免原始异常暴露。

## 3. 数据库设计
### 3.1 设计原则
1. 不使用外键约束，关联通过字段值逻辑维护，应用层保证一致性
2. 主键均采用自增BIGINT（除teacher_id外），teacher_id为业务唯一标识
3. 所有核心表添加**软删除字段**`is_deleted TINYINT DEFAULT 0`，禁止物理删除
4. 适当冗余（教师姓名、审批人姓名）以减少联表查询
5. 敏感字段AES加密存储（身份证、密保答案）
6. 为常用查询字段建立索引，优化查询性能

### 3.3 teacher_id生成策略
**结构**：`[身份码][年份后两位][月份][3位序号]` 共8位
- 身份码：1-普通教师,2-领导,3-管理员
- 示例：`12605001` = 普通教师 + 26年5月 + 序号001

**生成方式**：
1. 调用Redis `INCR teacher_id:seq:{prefix}`，前缀为身份码+年月（如`12605`）
2. 返回自增值格式化为3位，组装成完整teacher_id
3. 检查teacher_info表唯一性，确保不重复
4. Redis不可用时回退到数据库序列表`teacher_seq`维护每月计数

## 4. API接口设计
### 4.1 通用规范
- 基础路径：`/api/v1`
- 认证方式：Bearer Token (JWT)，Header: `Authorization: Bearer <access_token>`
- 成功响应格式：
```json
{
  "code": 200,
  "data": {},
  "message": "success"
}
```
- 错误响应格式：
```json
{
  "code": 400,
  "data": null,
  "message": "参数错误",
  "error": "详细错误信息"
}
```
- 分页请求参数：`page`(默认1), `page_size`(默认10,最大100)

## 5. 全局异常处理设计
### 5.1 自定义异常类
```python
# app/core/exceptions.py
class BaseException(Exception):
    code: int = 500
    message: str = "服务器内部错误"
    
    def __init__(self, message: str = None, code: int = None):
        if message:
            self.message = message
        if code:
            self.code = code

class BusinessException(BaseException):
    code = 400
    message = "业务异常"

class AuthenticationException(BaseException):
    code = 401
    message = "认证失败"

class AuthorizationException(BaseException):
    code = 403
    message = "权限不足"

class NotFoundException(BaseException):
    code = 404
    message = "资源不存在"

class RateLimitException(BaseException):
    code = 429
    message = "请求过于频繁"

class FileUploadException(BaseException):
    code = 400
    message = "文件上传失败"
```

### 5.2 全局异常处理器
```python
# app/core/events.py
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from app.core.exceptions import BaseException
import logging

logger = logging.getLogger(__name__)

def register_exception_handlers(app: FastAPI):
    @app.exception_handler(BaseException)
    async def base_exception_handler(request: Request, exc: BaseException):
        return JSONResponse(
            status_code=200,
            content={
                "code": exc.code,
                "data": None,
                "message": exc.message,
                "error": str(exc)
            }
        )
    
    @app.exception_handler(Exception)
    async def global_exception_handler(request: Request, exc: Exception):
        # 记录未捕获异常日志
        logger.error(f"未捕获异常: {exc}", exc_info=True)
        return JSONResponse(
            status_code=200,
            content={
                "code": 500,
                "data": None,
                "message": "服务器内部错误",
                "error": "系统繁忙，请稍后再试"
            }
        )
```

## 6. 诸葛亮Agent设计（LangChain重构版）
### 6.1 整体架构
```
用户输入 → 会话管理器(Redis) → 意图识别 → LangChain AgentExecutor
                                 ↓
┌─────────────────────────────────────────────────────┐
│ 工具集 (Tools)                                       │
│ ├─ NL2SQL工具：查询/修改教师、课程、考勤、事务数据    │
│ ├─ RAG工具：检索学校规章制度、培训大纲、FAQ          │
│ ├─ 搜索工具：联网查询专业技术知识                    │
│ ├─ 游戏工具：二十四点、猜灯谜                        │
```

### 6.2 会话状态管理（Redis）

### 6.3 LangChain工具定义
```python
# app/services/agent/tools/nl2sql_tool.py
from langchain.tools import tool
from app.services.nl2sql_executor import NL2SQLExecutor

@tool(return_direct=False)
def execute_sql(query: str) -> str:
    """
    执行SQL查询并返回结果。
    只能使用SELECT、INSERT、UPDATE语句，禁止DROP、ALTER等危险操作。
    UPDATE/INSERT操作需要用户确认后才能执行。
    """
    executor = NL2SQLExecutor()
    return executor.execute(query)

# 其他工具类似定义：rag_query, web_search, play_24_points, guess_riddle等
```

### 6.4 NL2SQL优化（Few-Shot + Schema Linking）
#### 6.4.1 Schema Linking技术
- 提前将表结构和字段注释转换为向量存入Milvus
- 用户问题向量化后，检索最相关的表和字段
- 只将相关表结构注入提示词，减少上下文长度和干扰

#### 6.4.2 Few-Shot示例
```python
# app/services/agent/prompt_templates.py
NL2SQL_PROMPT = """
你是一个SQL专家，根据以下表结构生成正确的SQL语句。

表结构：
{schema}

示例：
用户：我的课表
SQL：SELECT course_name, schedule_info, location FROM teacher_course WHERE teacher_id='{user_id}' AND semester='2025-2026-2' AND is_deleted=0

用户：张三这个月的考勤
SQL：SELECT check_date, check_in_time, check_out_time, status FROM attendance_record WHERE teacher_name='张三' AND check_date BETWEEN '2026-05-01' AND '2026-05-31' AND is_deleted=0

用户：帮我请假3天，从明天开始
SQL：INSERT INTO teacher_affair (teacher_id, teacher_name, affair_type, title, start_time, end_time, status) VALUES ('{user_id}', '{user_name}', 1, '事假', '2026-05-29', '2026-05-31', 1)

用户问题：{question}
SQL：
"""
```

#### 6.4.3 写操作确认机制
- 当生成INSERT/UPDATE语句时，Agent先返回操作预览
- 示例："主公，此操作将为您创建一条事假申请，时间为2026-05-29至2026-05-31，是否确认执行？"
- 用户回复"是"或"确认"后，再调用execute_sql工具执行
- 执行结果返回后，自动生成友好的自然语言回复

## 7. 安全设计
### 7.1 认证与授权
- 密码存储：bcrypt哈希，成本因子12
- 密保答案：AES-256-CBC加密，密钥从环境变量获取
- JWT：access_token有效期1小时，refresh_token有效期7天
- 权限控制：基于角色的访问控制(RBAC)，中间件统一校验

### 7.2 文件上传安全
- 白名单限制文件类型和大小
- 自动重命名文件，避免路径遍历攻击
- 上传目录设置为不可执行
- 禁止上传包含可执行代码的文件
- 定期扫描上传目录，清理恶意文件

### 7.3 输入与输出安全
- 所有接口参数使用Pydantic严格校验
- SQL注入防护：使用参数化查询，禁止字符串拼接
- XSS防护：输出内容自动转义
- 日志脱敏：密码、身份证、密保答案不写入日志
